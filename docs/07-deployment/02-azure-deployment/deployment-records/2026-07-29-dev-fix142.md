## 值得記錄

### cp1252 陷阱第四次命中

`az acr build` 本機串流在 `npx prisma generate` 的 `✔` 上崩潰、回 `exit 1`，雲端建置照常完成 —— 這已是連續第四次（7/28 三次 + 本次）。**本機 exit code 對這個指令沒有鑑別力**，一律走控制面 `az acr task show-run --run-id <id>`。

本次直接以背景輪詢 `show-run` 的 `status` 欄位直到脫離 `Running`，避免反覆手動查詢。

### 「乾淨部署」是可以事先證明的

過去部署的不確定性多半來自「不知道這一版到底帶了什麼上去」。本次用四道 `git diff <線上commit>..main -- <路徑>` 把風險面逐一證明為空集合（schema / 依賴 / env / 建置腳本），部署前就能斷言「重啟不會觸發任何一次性行為、不需補任何設定」。事後 log 完全符合預期。

這比「部署完再看 log 有沒有爆」便宜得多 —— 前提是**線上映像對應的 commit 有被記錄下來**（本次靠 2026-07-28 記錄第 6 行才查得到 `ddc270c`）。deployment-records 的價值就在這裡。
