部署前 `RUN_TEMPLATE_MAPPING_SEED` 仍是 `false`，**刻意保留**走完部署。若先清空，部署後只會得到 off-silent（無輸出），無法區分「修法生效」與「設定被清掉」。

於是取得**三段對照**（同一個旗標，三種條件）：

| 條件 | 容器 log |
|------|---------|
| FIX-140 前 + `false`（`dev-fix139`）| `[entrypoint] (optional) template field mapping seed: mode=false` ← **執行了腳本** |
| FIX-140 後 + `false`（`dev-fix140`）| `... seed skipped: mode=false not recognised (expected inspect\|dryrun\|write; clear the app setting to disable)` ← **跳過 + 說明** |
| FIX-140 後 + **清空**（設定變更後）| **該行完全消失** ← off-silent |

三種行為與本機的 `sh` 行為矩陣（RUN / skip-warn / off-silent）逐一對應，並證實 runbook §A.5 新寫的「清空才是真正的關閉」。

## 第 4 步：app settings 補齊（無映像變更）

### 補設定 `CONFIG_ENCRYPTION_KEY`

runbook §229 早記載此值**未設定**（FIX-070 為 fail-closed → 寫入加密系統設定會失敗，`admin/llm-providers` 新增 provider 亦然）。

**設定前先查證風險**：`.env.example:49` 明寫「一旦設定後不可變更，否則既有加密配置無法解密」，而 `:48` 的「**不再**以公開預設金鑰靜默加密」暗示 FIX-070 之前曾有預設金鑰 —— 若 DB 存有舊密文，設新金鑰會讓它們永久解不開。

查證結果：

| 檢查 | 結果 |
|------|------|
| `GET /api/admin/config` | 8 個 category **全部 `array[0]`** → `SystemConfig` 表零筆記錄 |
| Epic 23 `llm_providers` | 空表（FIX-138 驗收時確認）|
| 邏輯佐證 | `getConfigEncryptionKey()` 純 fail-closed、**絕不以硬編碼預設 fallback**（`src/lib/config-encryption.ts:47`）→ 金鑰未設時不可能產生密文 |

→ **零既有密文，設新金鑰零風險**。

| 項目 | 值 |
|------|-----|
| 產生方式 | `crypto.randomBytes(32).toString('hex')` |
| 長度 | 64 字元 hex（要求 ≥ 32）✅ |
| 存放 | Azure app setting（**非** Key Vault —— 部署 SP 僅 Contributor）|
| 安全處理 | 金鑰僅存在於執行期記憶體，`az` 呼叫全程 `--output none`；**未落盤、未輸出、未進 commit**。驗證只取 `name` / 長度 / 是否 hex，不取值 |

> ⚠️ 此金鑰**不可變更**。日後若需輪替，所有加密 `SystemConfig` 與 provider 憑證都需離線雙金鑰重加密（工具鏈不存在，見 Epic 23 senior review §三）。
> ⚠️ 真實安全等級 ≈「防 DB dump 外流」：金鑰與 app 同在 App Service env，進得了容器即取得明文。

### 清空 `RUN_TEMPLATE_MAPPING_SEED`

照 runbook §A.5 對非布林旗標的要求 `delete`（非設 `false`）。清空後該步驟完全靜默，即上方三段對照的第三段。

## 值得記錄

### `az acr build` 的 cp1252 陷阱（三次三中）

本機 exit 1、log 尾端 `UnicodeEncodeError: 'charmap' codec can't encode character '✔'`（`colorama/ansitowin32.py` → `encodings\cp1252.py`）。**這是顯示層崩潰，不是建置失敗** —— 雲端照常進行。三次都以 `az acr task list-runs` 的 `Succeeded` 判定。CHANGE-110 部署時曾誤判此訊號繞了十分鐘。

### `--query` 含大括號會被 cmd 解析壞掉

`--query "[?name=='X'].{name:name,chars:length(value)}"` 回 `} was unexpected at this time`。改由 PowerShell 端 `ConvertFrom-Json` 後篩選，順帶讓敏感值留在記憶體、只輸出長度。

### 「刻意保留錯誤設定」換到對照組

FIX-140 驗收若先清設定，就只會看到空白 —— 而空白既可能是修法生效、也可能是設定沒了。留著 `false` 走完部署，才拿到「執行 → 跳過 → 靜默」三段對照。
